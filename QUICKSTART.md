# Rani Shield: быстрый запуск

Откройте PowerShell в `F:\Git\rani-shield`. Для уже подготовленной установки:

```powershell
.\manage.cmd doctor
.\manage.cmd run
```

Откройте [http://127.0.0.1:7876](http://127.0.0.1:7876). Загрузите фото, выберите метод, нажмите **Protect photo**, затем **Export PNG**. Пропорции сохраняются, максимальная длинная сторона — **1280 px**; небольшие исходники не увеличиваются.

Команда `run` остаётся активной, пока работает сервер, и показывает логи в текущем терминале. После работы нажмите **Ctrl+C** в этом терминале.

Запуск сервера — отдельная команда. `setup`, `models`, `doctor`, `test` и справка его не запускают. Обычный `make` выводит справку. GNU Make необязателен: все действия доступны через `manage.cmd`.

## Подготовка новой установки

```powershell
.\manage.cmd setup
.\manage.cmd models
```

`setup` подготавливает локальный Python **3.11** в `.runtime/python/`, окружение `.venv` и **torch 2.7.1 + torchvision 0.22.1 / CUDA 12.8**. Для первоначальной подготовки используется установленный Python 3.11. Node.js, если доступен для копирования, помещается в `.runtime/node/` для проверок интерфейса. После подготовки интерпретатор, стандартная библиотека и Python-пакеты находятся внутри проекта. Нужны Windows, драйвер NVIDIA и браузер; отдельный CUDA Toolkit для готовых wheels не требуется.

`models` скачивает базовые веса в `weights/`. Полные архивы PhantomSeal нужно получить отдельно по ссылкам в [weights/README.md](weights/README.md). Из архивов нужны:

- `faceshifter/model_ir_se50.pth` → `weights/faceshifter/model_ir_se50.pth`.
- `hififace/hififace_opensource_299999.ckpt` → `weights/hififace/hififace_opensource_299999.ckpt`.
- Все **214 фото** из `data/vggface2_cloak/mix_full/` → `weights/phantomseal/cloaks/mix_full/`.

Для стандартной структуры дополнительных настроек не требуется. Если меняете расположение, оно должно оставаться внутри каталога проекта:

```powershell
.\manage.cmd configure -Checkpoints "weights" -Cloaks "weights\phantomseal\cloaks\mix_full"
.\manage.cmd doctor
```

`configure` сохраняет относительные пути и не копирует файлы. Внешние пути ресурсов отклоняются. `doctor` проверяет окружение, CUDA, все четыре ветви ансамбля и полную базу без загрузки весов в модели.

Однократный импорт из старой полной установки разрешён: он копирует ресурсы внутрь проекта, после чего старая папка для работы не нужна. План, параметры и инструкция переноса — в [weights/README.md](weights/README.md#import-an-existing-complete-installation). Личные фото и старое окружение импорт не переносит.

## Основные команды

| Действие | PowerShell | GNU Make |
|---|---|---|
| Подсказка | `.\manage.cmd help` | `make help` |
| Окружение | `.\manage.cmd setup` | `make setup` |
| Базовые веса | `.\manage.cmd models` | `make models` |
| Проверка готовности | `.\manage.cmd doctor` | `make doctor` |
| Запуск в текущем терминале (остановка — Ctrl+C) | `.\manage.cmd run` | `make run` |
| Другой порт | `.\manage.cmd run -Port 7877` | `make run PORT=7877` |
| Проверка занятого порта | `.\manage.cmd status` | `make status` |
| Остановка старого фонового сервера | `.\manage.cmd stop` | `make stop` |
| Тесты на CPU | `.\manage.cmd test` | `make test` |
| Проверка реальных моделей без сервера | `.\manage.cmd smoke` | `make smoke` |
| Справка по бенчмарку | `.\manage.cmd benchmark-help` | `make benchmark-help` |
| Сравнение 36 пар / 108 подмен | `.\manage.cmd benchmark` | `make benchmark` |
| Только первый исходник | `.\manage.cmd benchmark -Sources 1` | `make benchmark SOURCES=1` |

`manage.cmd run` и `make run` запускают сервер в текущем терминале, выводят логи напрямую и возвращают управление после завершения сервера. Они не создают фоновый сервер, запись PID или файлы серверных логов. `launch.ps1` вызывает тот же запуск; браузер автоматически не открывается.

Если порт занят или продолжает работать сервер, записанный старой версией, `run` отказывает в запуске: он не переиспользует и не останавливает существующий процесс. `status` можно вызвать из другого терминала для проверки порта. `stop` сохранён только для фоновых серверов старой версии: перед остановкой проверяются запись PID, время создания, путь Python и команда запуска. Текущий сервер останавливается через **Ctrl+C**, а не через `stop`.

Бенчмарк использует GPU и сохраняет результаты в `results/benchmarks/latest/`. Перед запуском дождитесь окончания обработки в интерфейсе. Чтобы указать отдельный каталог, добавьте `-OutputDir "results\benchmarks\trial"`. Обычные тесты не требуют сервера или GPU-бенчмарка.

`smoke` проверяет всю цепочку на GPU без запуска сервера: публичное фото увеличивается до 1280 px, обрабатывается за 10 + 1 шаг, затем создаются шесть реальных подмен для PNG/JPEG95. Сетевые обращения блокируются, пути загруженных Python-файлов и моделей записываются в отчёт внутри `results/verification/`. Это проверка исполнения и локальных зависимостей, а не доказательство эффективности защиты.

## Как читать проверку защиты

После обработки выберите **Test protection**, тестовое лицо и **Run SimSwap test**. **Also test JPEG95** добавляет сравнение после сжатия. Тестовое лицо задаёт человека/позу, в которые SimSwap пытается перенести вашу идентичность; ваш исходник показан отдельно.

Сначала сравните **Unprotected swap** с оригиналом. Если исходная подмена уже не похожа на вас, изменение оценки после защиты ничего не доказывает. Для PNG и JPEG95 отдельно отмечайте **The unprotected swap looks like me**, только если исходная подмена узнаваема. При слабом baseline или без подтверждения результат — **Inconclusive**, сравнительная разница скрыта.

Порог FaceNet **0.80** — числовой фильтр cosine similarity, а не «80% уверенности». Ни он, ни SSIM/PSNR не дают гарантии защиты. Тест проверяет использование фото как источника идентичности в одном SimSwap. Он не проверяет защиту от замены лица в самом загруженном фото как целевом изображении.

Текущие измерения не подтверждают надёжную защиту или преимущество второго этапа. Из 36 прежних сравнений только 8 проходят числовой фильтр baseline, причём это две исходные личности; визуальная проверка всё равно обязательна. Подробности — в [docs/VALIDATION.md](docs/VALIDATION.md).

## Авторы и условия использования

Особая благодарность [FaceShield (Why0912)](https://github.com/Why0912/FaceShield), с исследования которого началась работа, и [iccv25_faceshield (KUAICV)](https://github.com/kuai-lab/iccv25_faceshield), на коде и алгоритме которого построен этап защиты FaceShield. ## NullSwap и дополнительные проверки

В **Protection method** доступен **NullSwap · reconstruction** — реконструкция из PhantomSeal, а не оригинальная авторская реализация. В **Test protection → Face-swap model** доступны SimSwap, DiffSwap, InfoSwap и UniFace. Каждая проверка сначала должна показать узнаваемую подмену незащищённого фото; слабый baseline означает **Inconclusive**.

Для новой установки дополнительных моделей:

```powershell
.\manage.cmd import-models -Checkpoints "D:\downloads\checkpoints"
.\manage.cmd doctor
.\manage.cmd smoke-extra
```

Аналоги: `make import-models CHECKPOINTS="D:/downloads/checkpoints"` и `make smoke-extra`. Последняя команда проверяет NullSwap1280 и все четыре модели на PNG/JPEG95 без запуска сервера. В этой установке веса уже размещены и проверены в `weights/`; повторно скачивать их не нужно. Подробности: [NEW_MODELS.md](docs/NEW_MODELS.md).

Для NullSwap доступны **NullSwap strength** (0–4, по умолчанию ×1) и **NullSwap seed** (0–4294967295, по умолчанию 0). Они сохраняются в пресетах. При ×1 остаётся прежний предел 8/255, при ×2 — 16/255; ×0 сохраняет пиксели нормализованного оригинала. Усиление не гарантирует лучшей защиты.
